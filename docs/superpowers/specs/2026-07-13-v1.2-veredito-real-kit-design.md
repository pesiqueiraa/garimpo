# Garimpo v1.2 — Veredito BR real + Kit de validação: Design

**Data:** 2026-07-13 · **Fase:** 1 (MVP completo) · **Roadmap:** Features D, E e F da v1.2

## 1. Objetivo

Fechar o ciclo sinal → dossiê → **ação** com confiabilidade: o veredito de concorrência BR deixa de ser palpite do modelo e passa a vir de busca real no Google (Serper.dev), com links de evidência no dossiê; dossiês fortes (score final ≥ 8) saem com kit de validação pronto para usar na rua; e qualquer produto pode ser investigado manualmente via CLI.

Ao final da v1.2 começa o **congelamento obrigatório de 30 dias** (só uso, zero features).

## 2. Escopo

- **Feature D — Veredito BR real:** busca Serper com `gl=br&hl=pt` durante a escavação; LLM analisa os resultados e devolve veredito + evidências + score recalibrado. `products.br_verdict` e `opportunity_score` são atualizados (o radar aprende).
- **Feature E — Kit de validação:** para dossiê com `score_final >= 8`, o LLM gera copy de landing (headline, subheadline, 3 benefícios, CTA de lista de espera), 5 perguntas estilo Mom Test em português específicas do nicho, e mensagem de abordagem para grupos de WhatsApp do nicho. Anexado ao dossiê no e-mail.
- **Feature F — `--investigar`:** `python3 -m app.main --investigar "nome ou url"` escava qualquer produto na hora (fora do radar inclusive), salva HTML local com o dossiê, sem e-mail.
- **Fora de escopo:** busca no enriquecimento diário (25 produtos continuam com palpite rotulado); dashboard; qualquer feature de fases futuras.

## 3. Arquitetura (abordagem aprovada: dois módulos novos)

```
main.py ──> excavate.excavate_all / excavate.investigate ──┬─> search.py  (Serper + veredito)
                                                            ├─> kit.py     (kit de validação)
                                                            ├─> llm.py     (v1.1)
                                                            └─> db.py      (v1.1 + migração)
```

### 3.1 `app/search.py` — borda Serper + veredito

- `search_br(query: str, n: int = 8) -> list[dict]` — POST `https://google.serper.dev/search` com `{"q": query, "gl": "br", "hl": "pt"}`, header `X-API-KEY` (env `SERPER_API_KEY`, com `.strip()`). Timeout 10s. Retorna `[{title, url, snippet}]` do campo `organic`. Erro HTTP/timeout propaga para o chamador decidir.
- `verify_br_competition(product, competitors) -> tuple[dict, int, int] | None` — faz 2 buscas (`"app {niche} Brasil"` e a dor em forma de busca), monta prompt com os resultados + players da Play Store, chama `llm.ask_json` (reasoning minimal) e retorna `(dados, tokens_in, tokens_out)`, com `dados =`
  `{"verdict": "sem_concorrente"|"concorrente_fraco"|"concorrente_forte", "evidence": [{"title", "url", "why"}], "score_final": 0-10, "rationale": str}`.
  Retorna `None` (etapa pulada) se: `SERPER_API_KEY` ausente, Serper falhou nas duas buscas, ou LLM falhou — nesses casos os tokens gastos são 0 (falha de LLM descarta a chamada). Nunca levanta exceção para fora.

### 3.2 `app/kit.py` — kit de validação

- `build_kit(product, dossier_ctx) -> tuple[dict, int, int] | None` — 1 chamada `llm.ask_json` (reasoning `medium`, `max_tokens=2000`) com nicho, dor, clusters e veredito. Retorna `({"landing": {"headline", "subheadline", "benefits": [3], "cta"}, "mom_test": [5 str], "whatsapp": str}, t_in, t_out)`; `None` se o LLM falhar (kit é opcional, nunca bloqueia o dossiê).
- Valida a estrutura antes de retornar (3 benefits, 5 perguntas); estrutura errada = falha do kit, não do dossiê.

### 3.3 Orquestração em `excavate.py` (fluxo do dossiê v1.2)

1. Sugestão de concorrentes → Play Store → reviews → clusters *(v1.1, inalterado)*
2. **Veredito real:** `search.verify_br_competition(...)`. Se veio resultado: atualiza `products.br_verdict` e `products.opportunity_score = score_final`. Se `None`: dossiê segue com veredito-palpite rotulado.
3. **Ângulo de ataque** *(v1.1)*: prompt ganha bloco "resultados de busca no Google BR" quando o veredito real existir.
4. **Kit:** se `score_final >= 8` (só com veredito real), `kit.build_kit(...)`.
5. Persiste (`save_dossier` estendido), marca `done`, loga custo total (LLM + kit; buscas Serper custam ~US$0,001 e entram no log como contagem).
- Teto de custo continua US$0,25/dossiê, agora somando as chamadas extras. Estouro → `failed` (v1.1).

### 3.4 `--investigar` em `main.py`

- `python3 -m app.main --investigar "nome ou url"` entra em modo dedicado (sem coleta, sem e-mail):
  1. Procura produto por URL exata ou nome (case-insensitive `LIKE`); se não existe, `db.upsert` com `source="manual"`.
  2. Se `niche IS NULL`, enriquece só esse produto.
  3. `excavate.investigate(conn, product_id)` — mesma `_excavate_one`, ignorando fila/score/limite diário (re-escava mesmo se `dig_status='done'`, sobrescrevendo o dossiê — `INSERT OR REPLACE` da v1.1 já cobre).
  4. Salva `data/dossie-<slug>-<YYYY-MM-DD>.html` (renderização reutiliza `report._dossier_html`) e imprime o caminho.
  5. Falha → imprime erro e `sys.exit(1)`.

## 4. Dados (migração idempotente no `_migrate()`, padrão v1.1)

```sql
ALTER TABLE dossiers ADD COLUMN br_verdict_final TEXT;  -- veredito com busca real
ALTER TABLE dossiers ADD COLUMN br_evidence TEXT;       -- JSON [{title, url, why}]
ALTER TABLE dossiers ADD COLUMN score_final REAL;
ALTER TABLE dossiers ADD COLUMN kit TEXT;               -- JSON {landing, mom_test, whatsapp}
```

- `db.save_dossier` ganha parâmetros opcionais (default `None`) para os 4 campos — chamadas v1.1 continuam válidas.
- `db.dossiers_since` já retorna `d.*`, então os campos novos fluem para o relatório sem mudança.

## 5. E-mail (report.py)

- Bloco novo no dossiê, entre "Players encontrados" e "Mapa de dores": **"🇧🇷 Veredito de concorrência"** — veredito legível ("concorrente forte no Brasil" etc.), rationale curto e até 3 links de evidência (`title` clicável → `url`). Sem veredito real: linha discreta "palpite do modelo — sem busca real".
- Bloco **"🧰 Kit de validação"** ao final do dossiê (só quando `kit` existe): landing copy formatada, as 5 perguntas numeradas, mensagem de WhatsApp em bloco citável.
- Todo conteúdo dinâmico (inclusive `url`/`title` vindos do Serper) passa por `html.escape`; URLs só renderizam como link se começarem com `http`.

## 6. Falha graciosa (3 níveis, padrão do projeto)

| Falha | Comportamento |
|---|---|
| `SERPER_API_KEY` ausente | `[busca] SERPER_API_KEY ausente, veredito continua palpite` — dossiê sem bloco de evidência |
| Serper erro/timeout (2 buscas) | idem acima, `[busca] serper falhou: <erro>` |
| LLM do veredito falhou | idem — veredito real é etapa opcional |
| Kit falhou (LLM/estrutura) | `[kit] falhou para 'X'` — dossiê sai sem kit, continua `done` |
| Estouro do teto US$0,25 | dossiê `failed` (v1.1, inalterado) |
| `--investigar` falhou | erro no terminal + exit 1 (modo interativo) |

## 7. Testes (TDD, mock nas bordas, banco real temporário)

- `tests/test_search.py`: payload `gl=br&hl=pt` e header corretos; parse de `organic`; veredito com evidência; sem chave → `None` + log; erro HTTP nas 2 buscas → `None`.
- `tests/test_kit.py`: kit válido; estrutura inválida (2 benefits) → `None`; LLM falhou → `None`.
- `tests/test_excavate.py` (novos): veredito real atualiza `products.br_verdict` e score; kit presente quando `score_final >= 8`, ausente quando < 8; Serper fora do ar não derruba o dossiê; custo do kit soma no teto.
- `tests/test_db.py` (novos): migração das 4 colunas em banco v1.1; `save_dossier` retrocompatível.
- `tests/test_report.py` (novos): bloco de veredito com links escapados; bloco de kit; dossiê v1.1 (sem campos novos) renderiza igual.
- `tests/test_main.py` (novo): `--investigar` acha/cria produto e chama a escavação forçada (bordas mockadas).

## 8. Operacional

- Renomear `SERVER_API_KEY` → `SERPER_API_KEY` no `.env` local (usuário) e criar o secret `SERPER_API_KEY` no GitHub (usuário).
- `daily.yml`: adicionar `SERPER_API_KEY: ${{ secrets.SERPER_API_KEY }}` no bloco `env`.
- Custo estimado/dossiê: ~4 buscas Serper (US$0,004) + 1-2 chamadas LLM extras (~US$0,01-0,02). Bem dentro do teto.

## 9. Critérios de pronto (roadmap)

- [ ] Veredito BR com links de evidência em 100% dos dossiês gerados com `SERPER_API_KEY` presente.
- [ ] Kit de validação gerado junto do dossiê (score final ≥ 8) sem passo extra.
- [ ] `--investigar` validado de ponta a ponta com um produto real (HTML local com dossiê completo).
- [ ] Custo por dossiê continua < US$0,25 medido.

## 10. Depois da v1.2

**Congelamento de 30 dias** (regra do roadmap): zero código novo; uso diário, 1 kit executado na rua, `DIARIO.md` com aprendizados.
